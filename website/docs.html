Documentation

How to use Markdown Docs.

Everything the app does, how to use it, and how it works underneath. Your docs stay plain .md files on your own disk; the app reads, edits, searches and comments on them.

Mac or Linux?

Shortcuts here use ⌘ for macOS. On Linux, use Ctrl instead, and Finder is your Files app. The few shortcuts that differ by platform are listed in Keyboard shortcuts.

01Getting started

Install the app, open it, and write your first doc.

Install on macOS

Download the .dmg from the download section or GitHub Releases. It's a universal build for Apple Silicon and Intel Macs, and needs macOS 14 (Sonoma) or later.

The app isn't signed yet, so macOS blocks it the first time. Right-click the app and choose Open, or run:

xattr -dr com.apple.quarantine "/Applications/Markdown Docs.app"

Install on Linux

  • Ubuntu, Debian and similar: download the .deb, then install it: 
    sudo apt install ./Markdown-Docs_*_amd64.deb
    The app then appears in your applications menu.
  • Other distributions: download the .AppImage, make it executable with chmod +x Markdown-Docs_*.AppImage, and run it.

Builds are for 64-bit x86 machines. After the first install, the app updates itself.

Your first doc

  1. Open the app. The first time, it creates an empty docs folder for you (see Your docs folder for where).
  2. Click Create your first doc, or press ⌘N.
  3. Type a name, pick a template (Blank is fine), and click Create.
  4. Start writing in the Markdown editor. It saves itself a second after you stop typing.
  5. Press ⌘E to see the formatted preview.

The welcome screen lists your most recent docs, so you can pick up where you left off.

02Writing and viewing

Create docs, edit them, and see them formatted.

Docs and folders

Every doc is a normal .md file in your docs folder. Folders group them:

  • New doc: ⌘N, the pen icon at the top of the sidebar, or New doc here… in a folder's ⋯ menu.
  • Put a doc in a folder by naming it with a slash, such as team/standup. Missing folders are created for you.
  • Rename or delete from the ⋯ menu next to a doc or folder in the sidebar, or from the ⋯ menu at the top of an open doc.
  • Hidden items: files and folders whose names start with a dot, like .docs, don't appear in the sidebar. Folders with no docs in them aren't shown either.

The sidebar sorts naturally, so 2-intro comes before 10-summary.

The three views

The switch at the top of each doc picks how you see it:

ViewWhat you see
PreviewThe formatted doc. Select text here to comment on it.
SplitThe editor and a live preview side by side. The preview updates a moment after you stop typing.
MarkdownJust the editor, with syntax colors and line numbers.

⌘E flips between Preview and Markdown. New docs open in the editor so you can start typing.

Saving

  • Autosave: changes save a second after you stop typing. The header shows Saving…, then ✓ Saved. ⌘S saves straight away.
  • Safe writes: each save writes a temporary file and then swaps it in, so a crash can't leave a half-written doc.
  • Changed somewhere else: if another program changed the file since you opened it, the app asks before overwriting it.
  • If a save fails, or you decline to overwrite, autosave pauses and a Save button appears. Saving manually turns autosave back on.
  • Outside edits show up live. If you edit a doc in another editor, the app reloads it, unless you have unsaved changes, which always win.

The app asks before closing, quitting, or switching docs if there are unsaved changes.

What Markdown works

The preview supports GitHub-flavored Markdown and a bit more:

  • Headings, emphasis, lists, quotes, code, links and images
  • Tables, task lists (- [ ]), strikethrough, footnotes, and links that turn web addresses into links automatically
  • Code blocks are colored when you name the language, as in ```rust
  • Math with KaTeX: $inline$ and $$block$$
  • Diagrams with Mermaid, in a ```mermaid block
  • Raw HTML is allowed, but anything unsafe, such as scripts, is removed

The block of properties at the top of a doc isn't shown as text; it appears as a card instead.

Links between docs

Link to another doc with a relative path, optionally to a heading:

[Setup guide](../guides/setup.md#install)
  • Clicking it opens that doc at that heading.
  • #heading links scroll the current doc.
  • Web links open in your browser. Links never navigate the app window itself.

When you move or rename docs in the app, these links are updated automatically.

Images

Adding images

  • Paste a screenshot or copied image into the editor, or drag image files onto it.
  • The image is saved to an img/ folder next to the doc and linked where your cursor is, like ![shot](img/shot.png).
  • Nothing is overwritten: a second shot.png becomes shot-2.png. Pasted screenshots get a name with the date and time.
  • PNG, JPEG, GIF, WebP, SVG and AVIF are supported.

Images can also be any relative path, like ![](../shared/diagram.png), or a web address.

Viewing images up close

Click an image or Mermaid diagram in the preview to open it full-window:

  • Zoom: it opens fitted to the window. Click it to see actual size and click again to fit, or use the zoom buttons, + / −, 0 to fit, or ⌘ + scroll, which zooms around the pointer.
  • Pan: drag a zoomed image to move around it.
  • Next and previous: ← / → or the side arrows step through every image and diagram in the doc.
  • Close: Esc, the × button, or a click outside the image.

Diagrams grow to fill the window, since they're drawn as vectors and stay sharp. Images inside links follow the link instead of opening the viewer.

Export to PDF

Press ⌘P or choose Export PDF… from the ⋯ menu. The system print dialog opens with just the rendered doc, without the app's panels. Choose Save as PDF there. The doc's name is used as the file name.

03Finding things

Search across all your docs, or within the one you're reading.

Search

Press ⌘K, or click Search at the top of the sidebar.

  • Before you type, the popup shows your recent searches. Click one to run it again, or the × beside it to remove it.
  • As you type, it waits until you pause for a quarter of a second, then searches every doc's name and text, ignoring case.
  • Results list each doc with how many matches it has, and up to five of the matching lines with the match highlighted.
  • Click a line to open the doc at that exact match: highlighted in Preview, and selected in the editor. Click the doc's name to go to its first match.

What counts as a match

  • Text as you read it. Formatting symbols and link addresses are ignored, so the big docs finds **the big** [docs](https://example.com).
  • Text as written, too, so searching example.com still finds that link.
  • Property values, like a tag, but not property names. Otherwise status would match every doc. A property match only shows when the doc's text has no match.
  • Docs whose name matches come first, then docs with the most matches.

A search is remembered when you open one of its results, and the last ten are kept. They stay on your computer; manage them in Settings → Search.

Find and replace

Press ⌘F to find in the open doc. It works in all three views.

  • Type to highlight every match. The bar shows "3 of 12".
  • Enter goes to the next match, Shift+Enter to the previous one, and Esc closes the bar.
  • The Aa button turns on matching case.
  • Replace: press ⌥⌘F on macOS or Ctrl+H on Linux, or click the arrow at the left of the bar. Enter in the replace box replaces the current match and ⌘Enter replaces all.

Replacing changes the Markdown, so from Preview the app switches to Split view first.

Table of contents

The Contents tab in the right panel lists the doc's headings, from level 1 to 4. Click one to scroll there. As you scroll, the section you're in is shown in bold.

04Organizing

Keep docs tidy as they grow.

Moving and renaming

  • Drag a doc or folder onto a folder in the sidebar to move it there, or onto the empty space below the list to move it to the top level. Hovering over a closed folder while dragging opens it.
  • Rename from the ⋯ menu. Typing a path like archive/standup moves it too.

Nothing is ever overwritten. After a move or rename, the app updates relative links and images so they still work, both in the moved docs and in every doc that links to them. Links inside code blocks are left alone. Comments and version history move along too.

Move in the app

If you move or rename docs in Finder or another tool, links aren't updated, and the doc's comments and history are left behind.

Deleting

Deleting a doc or folder moves it to the system Trash, so you can get it back from there. Its comments and version history are deleted.

Properties

A doc can start with a block of properties, between two --- lines. This is called YAML front matter, and other Markdown tools understand it too.

---
title: "Kickoff"
description: "Plan for the first sprint."
tags: [meeting, q4]
status: draft
created: 2026-10-29
updated: 2026-10-29
attendees: [Priya, Sam]     # add any fields you like
---
  • In Preview, they appear as a card above the doc:
    • a colored chip for the status (draft, review, final, archived and so on)
    • #tag chips
    • the created and updated dates
    • the description
    • any other fields as a small list
    The title is shown only if it's different from the doc's first heading.
  • Edit them in the Markdown view. If the block can't be read, the card says so.
  • Saving sets updated to today. Only that line changes, and your cursor stays where it is.
  • They aren't part of the text: properties don't appear in PDFs or in the word count. Search looks at their values.

Docs you already had

The first time the app opens a docs folder, every doc without properties gets the default ones:

  • The title comes from the doc's first heading, or its file name if it has none.
  • The dates come from the file.
  • A message tells you how many docs changed.
  • Each doc's original text is saved in its version history first, so nothing is lost.

This happens once per folder. For a doc added later, choose Add properties from its ⋯ menu.

Templates

When you create a doc, pick a template for it to start from. Four come with the app:

TemplateStarts with
BlankDefault properties and a heading
Daily noteThe daily tag, a to-do list and notes
Meeting notesThe meeting tag, attendees, agenda, notes, decisions and action items
SpecThe spec tag, an owner, and sections for summary, problem, proposal, alternatives and open questions

Templates are ordinary .md files in the .docs/templates/ folder inside your docs folder. To manage them:

  • Settings → Templates lists them, and Open folder opens that folder, where you can edit, add or delete templates.
  • ⋯ → Save as template… turns the current doc into a new template.

These placeholders are filled in when a doc is created:

PlaceholderBecomes
{{title}}The doc's name
{{date}}Today, as 2026-10-29
{{time}}The time, as 14:32

Word count

The doc header shows how many words the doc has. Hover over it for the reading time, at about 230 words a minute. Link addresses, image paths, HTML tags, checkboxes and properties aren't counted. Chinese and Japanese characters count one each.

05Version history

Go back to an earlier version of any doc.

Open the History tab in the right panel, or choose Version history from the ⋯ menu. Versions are listed by day, newest first.

  • Click a version to see it in place of the doc:
    • Changes shows what's different from the current text, line by line, with long unchanged stretches folded away.
    • Preview shows how that version looked.
  • Restore puts that version back. Your current text is saved as a version first, so you can change your mind.
  • × or Current version takes you back to the doc.

When versions are kept

Before a save replaces a doc's text, the old text is kept, at most once every 5 minutes. Each version is labeled with when that text was saved. Over time, older versions are thinned out:

AgeKept
Up to a dayEvery version
Up to a weekOne per hour
Up to 90 daysOne per day
OlderOne per week
Good to know
  • Versions live in .docs/history/ inside your docs folder, so they sync and move along with your docs.
  • Only saves made in the app create versions. Edits from other editors are kept the next time the app saves the doc.
  • Restoring doesn't change comments.

06Comments

Leave notes in the margins, pinned to the words they're about.

  • Comment on text: select text in Preview and click the Comment button that appears.
  • General note: choose Add note from the ⋯ menu for a comment that isn't tied to any text.
  • Write the comment, then press ⌘Enter to save it, or Esc to cancel. Comments can use Markdown.
  • Threads support replies, editing, deleting, and resolving and reopening.
  • Highlights: commented text is highlighted in the preview. Click a thread to jump to its text, and the Comments tab shows how many open threads there are.

If the commented text is deleted or changed, its thread is flagged as no longer found, but it isn't lost.

Comments are stored in .docs/comments.db in your docs folder, never in the .md files, so your docs stay clean.

07Layout and settings

Arrange the window the way you like it.

Panels and focus mode

  • Sidebar: hide or show it with ⌘\. It holds your docs.
  • Right panel: hide or show it with ⇧⌘\. It holds the Contents, Comments and History tabs.
  • Resize either panel by dragging its edge, and double-click the edge to reset it. Sizes are remembered.
  • Focus mode (⇧⌘F) hides both panels so only the doc is left. Esc leaves it.
  • Narrow windows: the right panel opens over the doc instead of beside it.

The app follows your system's light or dark setting.

Settings

Open Settings with ⌘, or the button at the bottom of the sidebar.

SectionWhat's there
AppearancePick any font installed on your computer for the interface and docs, and for code and the editor
Docs folderSee where your docs are stored, and change it
TemplatesSee your templates and open their folder
SearchSee, remove or clear your recent searches
UpdatesTurn the automatic update check on or off, check now, and find links to the website, release notes and issue tracker

The app's own menu also has Visit Website, Check for Updates… and About.

08Your docs folder

Where everything is stored, and how to keep it in sync.

By default, docs live in the app's own data folder:

SystemDefault docs folder
macOS~/Library/Application Support/dev.thakurcoder.markdown-docs/Docs/
Linux~/.local/share/dev.thakurcoder.markdown-docs/Docs/

Press ⇧⌘R, or click the folder icon at the bottom of the sidebar, to open it in your file manager. Inside it:

Docs/
├── welcome.md            a doc is a plain Markdown file
├── team/
│   ├── standup.md
│   └── img/shot.png      pasted images go next to the doc
└── .docs/                the app's own data, hidden from the sidebar
    ├── comments.db       all comment threads
    ├── history/          earlier versions of each doc
    └── templates/        templates for new docs

Preferences (settings.json) and your chosen folder (location.json) are kept in the app's data folder, outside the docs folder. Recent docs and recent searches stay on each computer.

Using a different folder

In Settings → Docs folder, click Change… and pick any folder, such as one in Dropbox, Google Drive or Syncthing, to use your docs on several computers.

  • The app offers to copy your current docs and comments across. If any file would clash, nothing is copied.
  • Your old folder is left exactly as it was.
  • If the chosen folder can't be found when the app opens, for example an unplugged drive, it opens the default folder and tells you.
  • Use default folder switches back.
Syncing tip

Comments are kept in a single database file. Avoid editing comments on two computers at the same time in a synced folder, or your sync service may create a conflicted copy.

Existing Markdown files

When you point the app at a folder of existing Markdown files, it adds properties to each one the first time. The originals are kept in version history.

09Updates

The app keeps itself current, and only installs when you say so.

  • When the app opens, it checks for a new version. You can also choose Check for Updates… from the app menu, or use Settings → Updates.
  • If one is available, a message offers Update. It downloads, checks the update's signature, installs it, and offers Restart.
  • Linux .deb installs ask for your password, because the package is installed for the whole system.
  • If you have unsaved changes, you're asked before the app restarts.
  • Turn off the automatic check in Settings → Updates.

Updates come from the project's GitHub Releases. Each one is signed when it's built, and the app refuses any update whose signature doesn't match. Release notes are linked from Settings → Updates.

11Troubleshooting

macOS says the app can't be opened

The app isn't signed yet. Right-click it and choose Open, or run xattr -dr com.apple.quarantine "/Applications/Markdown Docs.app".

An update isn't offered right after a release

GitHub can take a few minutes to serve a new release to the update check. Try Check for Updates… again shortly.

The app opened an empty or different folder

If your chosen docs folder can't be found when the app opens, for example on an unplugged drive or a sync folder that isn't mounted yet, the app uses the default folder and shows a message. Reconnect the drive and choose the folder again in Settings → Docs folder.

An image doesn't show

  • Check the path is relative to the doc, like img/shot.png.
  • Images inside folders whose names start with a dot aren't loaded.
  • Images from the web need an internet connection.

Comments disappeared after moving a doc

Comments follow a doc only when it's moved or renamed in the app. Moving it back in your file manager to its old name and folder brings them back.

I want a doc's text from before properties were added

Open the doc's History tab. The version from just before the properties were added holds the original text, and Restore puts it back.

A font I picked doesn't change anything

On macOS, some installed fonts aren't available to apps like this one. The app warns you when that happens and uses its default font.

A conflicted copy of comments.db appeared

That's your sync service keeping two versions after comments were edited on two computers at once. The app uses comments.db; the conflicted copy can be deleted once you've checked you don't need it.

Something else is wrong

Please open an issue with what you did and what happened.

12Limitations

  • Platforms: macOS and Linux only for now; there's no Windows build.
  • Search size: search reads every doc each time, so it's instant for hundreds of docs, but not built for tens of thousands.
  • Search phrases: a phrase split across two lines of the source isn't found.
  • Search in diagrams: a match inside a Mermaid diagram scrolls near it rather than highlighting the word.
  • Outside edits: version history only captures saves made in the app.
  • One person: there are no comment authors, real-time collaboration or multiple libraries yet.

13Under the hood

How the app is built, for the curious and for contributors.

Architecture

Markdown Docs is a Tauri app with two halves:

  • The backend, written in Rust, does everything that touches the disk: reading and saving files, search, moving docs, comments, version history, templates, and turning Markdown into safe HTML.
  • The frontend, written in React and TypeScript, is the interface. It runs in the system's own web view (WebKit on both macOS and Linux) and asks the backend for things through commands.

The backend sends events the other way, such as "a file changed" or "a menu item was clicked". Using the system web view instead of bundling a browser keeps the app around 10 MB.

What it's built with

PartTechnology
App shellTauri 2: native window, menus, and the bridge between the halves
InterfaceReact 19, TypeScript, Vite, Tailwind CSS 4, shadcn/ui and Base UI
EditorCodeMirror 6, which also powers find and replace
Markdown to HTMLcomrak (Rust), then ammonia to remove anything unsafe
Code, math, diagramshighlight.js, KaTeX, Mermaid
Propertiesjs-yaml
CommentsSQLite
Watching for changesnotify (FSEvents on macOS, inotify on Linux)
UpdatesTauri's updater, with signed releases from GitHub
FontsGeist, Fraunces, Newsreader and IBM Plex Mono, bundled so the app works offline

Keeping your docs safe

  • Paths: every path the interface asks for is checked to stay inside your docs folder, so neither ../ tricks nor links to files outside the folder can reach other files.
  • Saves go to a temporary file that's then swapped in, and the file's modified time is checked first to catch changes from other programs.
  • Rendered HTML is cleaned in Rust before it's shown. The app also only allows its own scripts to run, and Mermaid runs in its strict mode.
  • Deleting uses the system Trash.

How search finds the exact spot

  1. Search compares each line of each doc, first with formatting removed and then as written.
  2. Each match comes back with its line number, which occurrence it is on that line, and the text around it.
  3. When the preview is rendered, every block is tagged with the source lines it came from.
  4. Clicking a result finds the block for that line, counts to the right occurrence, and highlights it using the browser's highlight feature, which marks text without changing the page.

Not changing the page matters, because comments remember their position by counting characters in the preview text.

How comments stay attached

Each comment stores the text it quotes and that text's position in the preview. To place the highlight, the app checks that position first, then looks for the first place the quote appears. If it's nowhere, the thread is flagged.

How version history is stored

Each doc has a folder in .docs/history/, named after the doc's file. Each version is a plain .md file named with the time its text was saved, in milliseconds. The Changes view compares two versions line by line, finding the longest run of lines they have in common.

For more detail, including where each feature lives in the code, see the guide in the repository: docs/how-it-works.md.

14Building from source

Run the app from its code, test changes, and publish a release.

Requirements

  • Rust (stable) and Node.js 20.19 or later, with npm
  • macOS: macOS 14 or later and the Xcode Command Line Tools (xcode-select --install)
  • Ubuntu or Debian: 
    sudo apt install build-essential pkg-config libwebkit2gtk-4.1-dev libxdo-dev libssl-dev \
  libayatana-appindicator3-dev librsvg2-dev

Run and test

git clone https://github.com/thakurcoderz/markdown-docs.git
cd markdown-docs
npm install
npm run dev                 # run with live reload

npm test                    # frontend tests
cd src-tauri && cargo test  # backend tests

Build an installable app

npm run build                        # macOS: .app and .dmg
npx tauri build --bundles deb        # Linux: .deb (add ,appimage for an AppImage)

The results are in src-tauri/target/release/bundle/.

Installing your own build over the same version

If the build has the same version number as the app you have installed, apt may decide there's nothing to do. Use sudo dpkg -i "path/to/Markdown Docs_<version>_amd64.deb" instead.

Publishing a release

  1. Bump the version in package.json, src-tauri/Cargo.toml and src-tauri/tauri.conf.json, then commit.
  2. Push a matching tag, such as git tag v1.2.0 && git push origin v1.2.0.
  3. GitHub Actions builds the macOS app and the Linux packages, signs the update files, and publishes one release with checksums. Installed apps then see it as an update.

Pull requests are welcome. Every push runs the tests in CI.
